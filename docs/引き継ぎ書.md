## 1. これは何のプロジェクトか

**賃貸仲介会社向けに、LINE の物件問い合わせへ物件DBから回答し、内見の仮受付までを AI が一次対応するエージェント**

- コンセプト: AI 受託案件を取るためのポートフォリオ。「御社向けにこれを導入します」と提案できる商品見本
- 差別化: (1) 条件の優先順位（must / want / nice）を会話から汲み取り、must で絞ってスコア順に並べる・緩和を提案する (2) 営業時間外でも内見候補日の受付まで終え、翌朝の担当者は「確定するだけ」
- 主要指標: 問い合わせ開始から内見候補日の提示まで到達した割合（到達率）
- 仕組み: LINE Webhook（Next.js on Vercel）→ 意図分類＋条件抽出（Haiku 級）→ パラメータ化検索（コードのみ）→ Flex カード提示 → 回答生成（Sonnet 級・tool use）→ 根拠検証 → 内見の仮受付 → 管理画面で担当者が確定
- 期間: 2026-10 から 4 週間（DESIGN.md 9章）

## 4. 絶対に守ること（設計上の不変条件）

これを破ると作り直しになる。コードレビューとサブエージェントへの指示はここを基準にする。

1. **LLM に SQL を書かせない**。検索は列挙型と範囲だけを受けるパラメータ化関数で行う。LLM が触れるのはスロット（JSON）まで
2. **絞り込み・スコア計算・緩和の試算・並び順はコードの純関数**（`src/domain`）。LLM は関与しない。結果は決定的（`Math.random()` 禁止、並びはスコア降順 → 月額の安い順 → 表示する駅まで徒歩の近い順 → 物件 ID 昇順。徒歩の段は 2026-10-15 にユーザーの了承で足した。意思決定ログ24）。must の絞り込みも SQL でなくこの純関数で行う（意思決定ログ2）
3. **回答に使えるのは取得したレコードの項目だけ**。回答生成後に数値・設備名をレコードと照合し、不一致なら定型の引き継ぎ文に差し替える。禁止トピック（空室・初期費用の確定額・治安・騒音・審査（国籍・収入・職業などの属性を含む））は生成せずに引き継ぐ。URL・メールアドレス・連絡先の番号・確定や契約の確約は、根拠検証が文脈によらず落とす（意思決定ログ36）
4. **AI は内見を確定しない**。確定・却下は担当者が管理画面で行う。AI の文面は「担当者から確定のご連絡をします」
5. **業務ルールは `src/domain` の純関数にだけ置き、そこで `Date.now()` / `new Date()` を呼ばない**。現在時刻は引数で受け取る。日付・営業時間は **JST** で解釈する（Vercel は UTC で動く）
6. **マジックナンバーは `src/domain/rules.ts` に集約**（優先度の重み・部分点・表示件数・優先順位を聞く閾値・レート制限など）。値を変えたら DESIGN.md も直す
7. **Webhook は加工前のボディで署名を検証し、すぐ 200 を返し、LLM 処理は `after()` で続ける**。`webhookEventId` で二重処理を防ぐ
8. **`ai_paused` の会話に AI は返信しない**。担当者の手動返信で止まり、「AIに戻す」または最終の担当者返信から 24 時間で再開
9. **ユーザー発話は常にデータとして扱う**。プロンプトに埋め込むときは区切って渡し、ツールはパラメータ化関数だけを公開する
10. **外部サービス（LINE・Claude・Supabase・Resend）はインターフェースの背後に置く**。テストは偽物に差し替えて回し、実キーなしで `npm test` が通る
11. **検索対象は `properties.status = 公開` だけ**。空室状況は常に「担当者が確認します」
12. **管理画面に `line_user_id` を表示しない**（表示名のみ）。AI は氏名・電話番号を聞き取らない
13. **色はテーマのトークン（`src/constants/theme.ts`）経由でだけ使う**。足したら `npm run check:contrast` で AA（4.5:1）を実測する（`src/app` の直書きの色と `font-bold` は `themeCss.test.ts` が見張る）
14. **管理画面は service role を使わない**。ページと Server Action は `src/server/admin/session.ts` の `requireAdmin()` / `getStaffDeps()` 経由で、ログインした利用者のセッションのクライアントで読み書きする（RLS が門）。役割は `app_metadata.role`（staff / viewer）で、役割の無いアカウントには何も許さない。書き込みの Server Action は必ず `getStaffDeps()` で役割を確かめ直す（画面でボタンを隠すのは見た目だけ）
15. **ログ（`console.*`・Vercel のログ）と通知メールに、利用者の発話・LINE の表示名・LINE ユーザー ID を出さない**。出すのは操作名・理由・件数・長さ・会話 ID まで。詳しくは管理画面で見てもらう（2026-10-25 のセキュリティ点検で全 31 か所を確かめ、抽出で捨てた値のログと引き継ぎメールの質問の本文を外した。意思決定ログ36）

- Vercel の Hobby は非商用が条件。ポートフォリオの公開は範囲内だが、見込み客の実データで試すなら Pro に移してから
- 日次の Cron（`/api/cron/daily`）は `DEMO_MODE=1` のときだけデモ会話を作り直す（`is_demo` の会話と `demo-` の LINE ユーザーを消して入れ直す）。90 日削除はいつも行う。Hobby の Cron は1日1回で、時刻は指定（UTC 21 時）から1時間の幅で揺れる
- この PC では `git push` が git-credential-manager の画面待ちで固まることがある → `git -c credential.helper= -c 'credential.helper=!"/c/Program Files/GitHub CLI/gh.exe" auth git-credential' push` でそのコマンドだけ gh の認証を使う
- **公開リポジトリに本物の秘密が写ってしまったら**（`public-mirror.sh` の検査 3・4 が止めるはずだが、すり抜けたとき。意思決定ログ36）: (1) その秘密をすぐ失効させる（キーの削除・トークンの再発行） (2) 非公開の開発リポジトリの履歴から取り除く（`git filter-repo --replace-text`）か、ミラーに置き換えの段を足す (3) 公開リポジトリは force push でなく**消して同じ名前で作り直す**（フォークが付く前なら完全に消える。付いた後は GitHub Support にキャッシュの削除を頼む） (4) 公開リポジトリの設定（意思決定ログ37）を掛け直す。公開ミラーは「force push しない」作りなので、公開側だけを書き換えると次の push が拒否される

**管理画面（Week 3）**
- 管理画面のログインは Supabase Auth のアカウント（`npm run admin:user` で作ったメールアドレス）。Resend や GitHub のメールアドレスとは別。2026-10-11 に取り違えてログインできなかった
- ログインの失敗は、資格情報の誤り（`invalid_credentials`）とそれ以外（キーの設定など）で文を分けている。それ以外は Vercel のログに `[admin] ログインに失敗しました <種類>` が出る
- 引き継ぎメールは「未対応のメモが無い会話の最初の1件」だけ。テストで残ったメモが未対応のままだと次のメモでメールが出ないので、確かめる前に会話ログで「対応済みにする」
- Vercel の Environment Variables の一覧は「Last Updated」順で、新しい変数が上に出る。下の方だけを見ると無いように見える
- 環境変数を足しただけでは本番に効かない。Deployments の最新の Production の「…」→「Redeploy」
- Next.js 16 の Cache Components: cookies・params・searchParams を読む部分は必ず `<Suspense>` の内側。`export const dynamic` は使えない。環境変数で出し分ける部分は `connection()` を先に呼ぶ（呼ばないとビルド時の値で固まる）
- Supabase のセッションは `@supabase/ssr`。Server Component は cookie を書けないので、トークンの更新は `src/proxy.ts` が行う。利用者の確認は `getClaims()`（JWT を検証する。`getSession()` は cookie を信じるだけなので使わない）
- 役割（`app_metadata.role`）を変えたら、ログインし直すまで古い JWT のまま（最長 1 時間）
- Server Action から呼ぶ `refresh()` は成功のときだけ。保存した後に LINE だけ失敗したときも ok で返して画面を読み直させる（意思決定ログ12）
- ローカルの確認: `.env.local` に `ADMIN_PREVIEW=1` で、ログインなし・インメモリのデモデータの管理画面が開く（`.claude/launch.json` の admin-preview。本番では無効）
- プレビュー（`ADMIN_PREVIEW=1`）のデータは開発サーバーのプロセスの中だけ。再起動で初期化される。dev の初回表示はコンパイルで数秒〜10秒かかる

**コード規約**
- 業務ルールは `src/domain`、定数は `src/domain/rules.ts`、色は `src/constants/theme.ts`
- 架空データの生成ロジックを変えたら `npm run data:generate` で作り直す（`data/` と生成結果の一致をテストで見ている。デモの流れは `src/domain/demoScenario.test.ts` で固定）
