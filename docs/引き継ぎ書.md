## 1. これは何のプロジェクトか

**賃貸仲介会社向けに、LINE の物件問い合わせへ物件DBから回答し、内見の仮受付までを AI が一次対応するエージェント**

- コンセプト: AI 受託案件を取るためのポートフォリオ。「御社向けにこれを導入します」と提案できる商品見本
- 差別化: (1) 条件の優先順位（must / want / nice）を会話から汲み取り、must で絞ってスコア順に並べる・緩和を提案する (2) 営業時間外でも内見候補日の受付まで終え、翌朝の担当者は「確定するだけ」
- 主要指標: 問い合わせ開始から内見候補日の提示まで到達した割合（到達率）
- 仕組み: LINE Webhook（Next.js on Vercel）→ 意図分類＋条件抽出（Haiku 級）→ パラメータ化検索（コードのみ）→ Flex カード提示 → 回答生成（Sonnet 級・tool use）→ 根拠検証 → 内見の仮受付 → 管理画面で担当者が確定
- 期間: 2026-10 から 4 週間（DESIGN.md 9章）

## 4. 絶対に守ること（設計上の不変条件）

これを破ると作り直しになる。コードレビューとサブエージェントへの指示はここを基準にする。

1. **LLM に SQL を書かせない**。検索は列挙型と範囲だけを受けるパラメータ化関数で行う。LLM が触れるのはスロット（JSON）まで
2. **絞り込み・スコア計算・緩和の試算・並び順はコードの純関数**（`src/domain`）。LLM は関与しない。結果は決定的（`Math.random()` 禁止、並びはスコア降順 → 月額の安い順 → 物件 ID 昇順）。must の絞り込みも SQL でなくこの純関数で行う（意思決定ログ2）
3. **回答に使えるのは取得したレコードの項目だけ**。回答生成後に数値・設備名をレコードと照合し、不一致なら定型の引き継ぎ文に差し替える。禁止トピック（空室・初期費用の確定額・治安・騒音・審査）は生成せずに引き継ぐ
4. **AI は内見を確定しない**。確定・却下は担当者が管理画面で行う。AI の文面は「担当者から確定のご連絡をします」
5. **業務ルールは `src/domain` の純関数にだけ置き、そこで `Date.now()` / `new Date()` を呼ばない**。現在時刻は引数で受け取る。日付・営業時間は **JST** で解釈する（Vercel は UTC で動く）
6. **マジックナンバーは `src/domain/rules.ts` に集約**（優先度の重み・部分点・表示件数・優先順位を聞く閾値・レート制限など）。値を変えたら DESIGN.md も直す
7. **Webhook は加工前のボディで署名を検証し、すぐ 200 を返し、LLM 処理は `after()` で続ける**。`webhookEventId` で二重処理を防ぐ
8. **`ai_paused` の会話に AI は返信しない**。担当者の手動返信で止まり、「AIに戻す」または最終の担当者返信から 24 時間で再開
9. **ユーザー発話は常にデータとして扱う**。プロンプトに埋め込むときは区切って渡し、ツールはパラメータ化関数だけを公開する
10. **外部サービス（LINE・Claude・Supabase・Resend）はインターフェースの背後に置く**。テストは偽物に差し替えて回し、実キーなしで `npm test` が通る
11. **検索対象は `properties.status = 公開` だけ**。空室状況は常に「担当者が確認します」
12. **管理画面に `line_user_id` を表示しない**（表示名のみ）。AI は氏名・電話番号を聞き取らない
13. **色はテーマのトークン（`src/constants/theme.ts`）経由でだけ使う**。足したら `npm run check:contrast` で AA（4.5:1）を実測する

## 8. ハマりどころ・注意点

**環境・リポジトリ**
- Next.js 16.4 は学習データと API が違うことがある。書く前に `node_modules/next/dist/docs/` の該当ガイドを読む（`AGENTS.md`）。雛形は `cacheComponents: true`
- 作業ツリーは OneDrive 配下（Windows・`core.autocrlf=true`）。`.gitattributes` で LF に固定している

**外部サービス**
- LINE: reply token は短時間で失効する（長引いたら push。push は月間枠を消費）。Flex カルーセルは最大 12 バブル、1 回の返信は最大 5 メッセージ、クイックリプライは最大 13 個。LINE Notify は終了済み
- Vercel: `after()` はレスポンス後も最後まで走ることを実機で確かめた（2026-10-10・Fluid compute 有効の既定のまま）。処理が `maxDuration = 60` を超えると打ち切られる
- Claude: Haiku 4.5 のプロンプトキャッシュは最小 4096 トークン（届かないと黙って効かない）。Sonnet 5.5 は `tool_choice` の強制と `temperature` が 400（`src/lib/llm/models.ts` で吸収）。料金表に無いモデルは `costUsd` が例外（費用上限が静かに狂うのを防ぐ）
- Supabase: Sign-ups は無効にし、担当者は招待で作る（authenticated を全員担当者として扱うポリシーのため。2026-10-07 に無効化済み）
- Supabase の新しい API キー（`sb_secret_…`）を `SUPABASE_SERVICE_ROLE_KEY` に入れる（supabase-js 2.117 で service role として使える）。すぐ上の `sb_publishable_…` は別物
- Supabase の SQL Editor を Chrome で操作するとき: SQL は PowerShell の `Set-Clipboard` で入れ、Monaco の「Editor content」にフォーカスしてから Ctrl+V（ページ全体の Ctrl+A になりやすい）。実行時の「Potential issue detected」は `revoke` や関数内の `delete` に反応しているだけ。未保存のクエリがあるとページ移動が「Leave site?」で止まるので、別のタブで開く
- LINE: Messaging API のチャネルは LINE Developers から直接は作れない。LINE 公式アカウントを作り（https://entry.line.biz/form/entry/unverified。SMS 認証が要る）、Official Account Manager の 設定 → Messaging API で「利用する」を押してプロバイダーを選ぶ（**一度選ぶと変更できない**）。その途中で「情報利用に関する同意」「LINEヤフーグループへの情報提供に関する個別規約」「LINE公式アカウントAPI利用規約」への同意を求められる。作成者は作成時に自動で友だちになり、LINE 既定のあいさつが届く
- LINE: 長期のチャネルアクセストークンの「Issue」を Claude in Chrome で押すと、タブが一時的に応答しなくなった（スクショが 30 秒で失敗）。少し待てば戻る。チャネルシークレットは「Basic settings」タブ、トークンは「Messaging API」タブの最下部。2つは取り違えやすい（シークレットは英小文字と数字の 32 文字）
- LINE: Webhook の「Use webhook」は URL を保存して「Verify」が通った後に出るトグル。オンになったかは `GET https://api.line.me/v2/bot/channel/webhook/endpoint` の `active` で確かめる
- Vercel: Hobby は関数のリージョンを 1 つだけ選べる（Settings → Functions → Function Region。既定は `iad1`）。変えたら Deployments の「…」→ Redeploy。効いているかはレスポンスヘッダー `x-vercel-id` が `hnd1::hnd1::…` か
- Vercel: 新規プロジェクトの Environment Variables の Key 欄に `.env.local` を丸ごと貼ると1行ずつに分かれる（コメントは無視）。値が空の行は消してから Create Project → Deploy
- Anthropic: キーは作成画面で有効期限（既定 30 日）とスコープを選ぶ。クレジットが無いとキーが正しくても 400 `credit balance is too low`。購入ボタンが押せないときは再読み込みで直った（2026-10-10）
- Claude Code の auto mode は、キーの先頭数文字を表示するコマンドも止める。キーの確認は「空か記入ありか」「長さ・形式の真偽」だけを出す
- この PC では `git push` が git-credential-manager の画面待ちで固まることがある → `git -c credential.helper= -c 'credential.helper=!"/c/Program Files/GitHub CLI/gh.exe" auth git-credential' push` でそのコマンドだけ gh の認証を使う

**コード規約**

- 架空データの生成ロジックを変えたら `npm run data:generate` で作り直す（`data/` と生成結果の一致をテストで見ている。デモの流れは `src/domain/demoScenario.test.ts` で固定）
